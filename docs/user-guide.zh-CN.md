# 用户手册

1. 在仓库外初始化私有目录：`paperrule init --workspace <私有目录>`。
2. 建立论文档案：`paperrule paper add --id <代号> --path <论文目录>`。
3. 导入 TXT/Markdown 意见：`paperrule ingest <文件> --paper <代号> --reviewer <来源代号>`。
4. 创建候选规则并通过本地 API 自由讨论。检查提案全文和哈希后才批准。
5. 对论文安装 Codex Skill：`paperrule install-codex --paper <论文目录>`。

PDF 原生批注提取需要可选 PyMuPDF；无文字批注不会自动补写意图。网页中已有保存回归案例、运行和查看历史报告的流程；模型语义判断依赖可用的真实提供方，当前尚未完成真实提供方效果验收。私有记忆同步还需要配置私有远端，双设备冲突处理流程尚未完成。

## 人工补录与纠错

在网页的“来源与意见”中导入材料，再点击左侧的来源档案。即使 PDF 没有可提取文字，也可以在“原件人工补录”中填写原文、补录原因、确认来源角色和分类。只有确知 PDF 页码时才填写页码；未知时留空，并用位置说明补充线索。保存会追加一条与原件关联的意见，不会替换原件或把原来的提取状态标成成功。

发现已导入意见的解释或分类有误时，展开该意见的“补充解释或纠错”，填写解释、依据和可选分类，再追加纠错记录。原话、原来源和历史纠错记录会保留。页面使用最新确认分类；筛选意见时也会搜索补充解释。若其他操作已经更改了同一条意见，需要刷新后核对最新内容再提交。

补录和纠错都不会批准提案或更改生效规则。整理长期规则时，点击“据此创建提案”，检查内容、适用范围和来源，再到审批中心明确批准当前版本。

若确认分类为“当前论文的一次性修改”，当前来源页面会禁用“据此创建提案”。后端在创建和审批时也会核对最新分类，阻止这类意见直接变成长期规则；只有明确重新分类后才能整理为可复用规则。一次性任务提案必须绑定一篇已建立档案的论文，且不能使用另一篇论文的意见作为依据。

确认一次性修改分类后，展开该意见下的“整理为论文修改任务”，选择已保存的论文，填写任务标题和具体修改内容，再点击“保存任务提案”。系统会打开审批中心；核对内容、所属论文和原始依据后，明确批准当前版本，任务才会保存。仅确认分类不会自动创建任务。

打开左侧“论文修改任务”可以查看已审批任务、按论文筛选，并通过“查看审批提案”回到当时批准的内容。展开依据可查看原始意见和后续补充。任务不会加入长期规则包，也不会自动修改论文。任务进度和完成状态的记录功能尚未提供。

这些补录与纠错功能目前属于本地开发版本，尚未包含在最新已发布提交中。整体产品仍有未完成的验收项，详见 [开发与验收记录](implementation-progress.md)。
